# Граф зависимостей Cargo

Практическая работа № 2, вариант 9. CLI читает INI и строит граф
прямых и транзитивных зависимостей рекурсивным обходом в глубину.
Требуется Python 3.8+ со стандартной библиотекой.

## Сборка, запуск и тесты

Команды из корня репозитория:

```sh
python3 -m compileall -q src
./run.sh examples/cargo.ini
python3 -m unittest discover -s tests -v
```

## Функции

| Функция | Назначение |
| --- | --- |
| settings.check_source | Проверяет URL индекса или существование локального файла. |
| settings.check_url | Проверяет схему, адрес, порт и отсутствие лишних частей URL. |
| settings.check_text | Отклоняет управляющие символы в параметрах. |
| settings.check_image | Проверяет расширение, каталог и доступ для записи изображения. |
| settings.load_settings | Читает INI, проверяет пять ключей, возвращает настройки и режим. |
| registry.index_path | Вычисляет путь записи пакета в sparse-индексе Cargo. |
| registry.dependencies | Читает индекс, раскрывает псевдонимы и возвращает прямые зависимости. |
| graph.read_repository | Возвращает списки смежности и версии локальных пакетов. |
| graph.read_package | Проверяет описание пакета и формат версии MAJOR.MINOR.PATCH. |
| graph.read_graph | Читает локальный JSON и проверяет имена, списки и ссылки. |
| graph.traverse | Строит граф рекурсивным DFS с фильтрацией и учётом циклов. |
| graph.traverse.visit | Посещает вершину один раз и рекурсивно раскрывает её зависимости. |
| main.run | Выбирает источник, строит граф и печатает списки смежности. |
| main.main | Разбирает аргумент командной строки, сообщает ошибки и код завершения. |

Пути repository и image отсчитываются от каталога INI. Каталог изображения
должен существовать и быть доступен для записи. Проверка image выполняется
без создания файла. Строка exclude допускает пустое значение и любые печатные
символы. Управляющие символы отклоняются для всех пяти параметров.

## Параметры секции graph

| Ключ | Значение |
| --- | --- |
| package | Имя пакета Cargo, в тестовом режиме — заглавные латинские буквы. |
| repository | HTTP(S)-адрес sparse-индекса Cargo или путь от INI к тестовому файлу. |
| test_mode | true для файла, false для сети. |
| image | Имя будущего изображения с расширением .svg. |
| exclude | Подстрока имени пакета. Пустое значение отключает фильтр. |

Все пять ключей обязательны. В сетевом примере корневой пакет — version_check.
Тест поочерёдно подставляет неверное имя, адрес, режим,
расширение и удаляет обязательный ключ exclude. CLI сообщает ошибку в stderr
и завершает работу с ненулевым кодом.

## Данные Cargo

Программа по HTTP читает JSON-строки sparse-индекса. Для каждого имени
используется последняя опубликованная неотозванная запись. Учитываются все
объявленные зависимости, включая optional, build, dev и целевые платформы.
Псевдонимы разворачиваются в имена пакетов, повторы удаляются.
Это граф объявлений по именам пакетов, без разрешения ограничений версий Cargo.

## Локальный граф и примеры обхода

Запустите `./run.sh examples/local.ini`. Файл graph.json задаёт каждый
пакет отдельным ключом, а значение — объектом с полями version и dependencies.
Поле version содержит версию MAJOR.MINOR.PATCH, dependencies — массив имён.
Даже лист должен иметь запись с пустым массивом. Результат:

```text
A@1.0.0: B@1.0.0 C@1.0.0
B@1.0.0: D@1.0.0
D@1.0.0: B@1.0.0
C@1.0.0: D@1.0.0
```

Порядок строк соответствует первому посещению в DFS. Ребро D → B замыкает
цикл, а D встречается в двух ветвях. Каждая вершина раскрывается один раз.

* Задайте `exclude = B` в копии INI рядом с оригиналом. Получатся строки
  `A@1.0.0: C@1.0.0`, `C@1.0.0: D@1.0.0`, `D@1.0.0:`. Фильтр учитывает регистр и отсекает всю ветвь,
  если до её потомков нет другого пути.
* Задайте `package = E` с пустым exclude. Результат — одна строка `E@1.0.0:`.
* При совпадении фильтра с корнем вывод пуст.

Параметр image зарезервирован для последующего этапа визуализации.

## Проверка этапов

Каждый коммит представляет самостоятельный этап. Чтобы запустить раннюю
версию, найдите её хеш командой `git log --reverse --oneline` и выполните
`git switch --detach ХЕШ`. После проверки вернитесь командой
`git switch main`.

На первом этапе команда `./run.sh examples/cargo.ini` печатает пять
параметров. На втором она печатает прямые зависимости. На третьем
`./run.sh examples/local.ini` показывает рекурсивный обход из примера выше.
Команда тестов одинакова для всех трёх этапов.

Тесты конфигурации проверяют отсутствие каждого обязательного ключа,
неверные значения, управляющие символы, локальный путь и доступ для записи.
Тесты графа проверяют цикл, общую вершину, фильтр, изолированный корень,
ошибочную структуру JSON и ссылки на отсутствующие вершины.

Сетевой пример использует небольшой пакет version_check. Сообщения загрузки
выводятся в stderr сразу, граф — в stdout после завершения обхода.
Для больших пакетов (например, serde_json) полный обход может быть долгим,
поскольку включает тестовые и необязательные зависимости.

В локальном выводе корень и зависимости имеют формат ИМЯ@ВЕРСИЯ.
Старые JSON-файлы со списками поддерживаются с версией 1.0.0 по умолчанию.
Фильтр применяется к имени пакета.
